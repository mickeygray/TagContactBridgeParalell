## Shipped

### Durability + safety

- **#1 Request timeouts.** `anthropicClient.createMessage` now accepts
  `timeoutMs` (default 25s, env `ANTHROPIC_TIMEOUT_MS`) using
  AbortController; hourly sweeper's `dispatchJob` wrapped in a 45s
  `withTimeout` helper. Timed-out handlers fail with `handlerTimedOut:
  true` flag so retries still apply (a hung handler once can succeed
  next time). Previously a stuck call could wedge the whole drain
  batch.
- **#6 JWT payload expanded.** `issueLoginToken` now includes
  `extensionNumber`, `phone`, `logicsUserId`, `logicsDisplayName`, all
  tenant-prefixed Logics fields (`tagLogicsId`/`tagEmail`/...,
  `wynnLogicsId`/`wynnEmail`/...), and a *sanitized* `logicsAuth`
  (mode/status/scopes/label only — never hashes). Frontend no longer
  sees nulls between login and the first `/me` refresh.
- **#7 Credential hash sanitization.** `decorateAccountRecord` strips
  `apiKeyHash`/`secretHash` from every API response (both `/auth/me`
  and `/admin/accounts/*`). `apiKeyLast4`/`secretLast4` preserved as a
  "which key is installed" visual cue. Rotation timestamps preserved.
  Rotation *endpoint* is still TODO — no way to install a new key via
  UI yet.

### Retry system

- **#10 Six new resolution checks registered** in
  `hourlyJobResolutionChecks.js`: `cx-logics-action-state` (workflow
  terminal), `outbound-delivery-state` (provider="delivered"),
  `recording-ready-state` (transcript exists or abandoned),
  `social-reply-state` (placeholder — no probe yet), `telephony-
  session-attributed` (CallLog.sourceCanonicalId populated),
  `auto-responder-delivery-state` (workflow touched by operator).
  Previously Codex's emissions referenced these 6 keys but the registry
  only had `logics-case-visible` + `payment-ledger-fresh` — handlers
  were running even when work was already done.
- **#23 Watchdog dedupe.** `emitWatchdogRetry` now uses
  `dedupeKey: "TAG:ringcentral-subscription:<reason>:<hour-bucket>"` so
  a 1-hour RC outage emits one retry job per cause, not 12 (one per
  5-min watchdog tick).

### Payment integrity

- **#11 Chargeback reversal.** New
  `caseProfileRepository.reversePaymentOnCaseProfile(domain, caseId,
  payment)` decrements `totalPaid`/`paymentsCount` and `$pull`s the
  paymentId. `paymentReconcileService` now snapshots prior ledger rows
  per case, and on SUCCESS→FAILED/PENDING transition calls the reversal
  + emits a `payment-chargeback` review item. Counters now stay honest
  over time.

### TCPA / cadence hardening

- **#3 TCPA quiet-hours + holidays + frequency caps.**
  `contactTimingPolicyService`:
  - Caps `contactEndHour` at **21** (TCPA hard limit); defaults to 20.
  - Voice, SMS, *and RVM* all treated as "restricted" (previously RVM
    was 24/7 — wrong for TCPA). Email stays 24/7.
  - US federal holiday blocklist (2026+2027) checked against
    recipient-local date.
  - Return shape distinguishes `reason: "holiday"` / `"quiet-hours"` /
    `"off-weekday"` / `"outside-contact-window"` so dispatcher can log
    the actual cause.
  - New `evaluateFrequencyCap(cadenceState, channel)` — pure function
    that checks `caps[c]` vs `completedByChannel[c] + pendingByChannel[c]`.
  `outboundDispatchService.dispatchForLead` now calls both. A cap-
  exhausted action gets `status: "cancelled"` (not just skipped) so
  the scheduler doesn't re-offer it.
- **#17 Eligibility check moved before action claim.** Previously we
  `claimScheduledAction` (flips to `requested`), then checked
  eligibility, which left blocked actions stuck in `requested`. Now
  blocked actions flip straight to `cancelled` with
  `currentStage: ${channel}-blocked`.
- **#5 Stale scheduled-action cleanup.**
  `leadCadenceRepository.cancelStaleScheduledActions({ olderThanMs =
  48h })` walks pending/requested actions past their scheduledFor and
  cancels them. Wired into Phase A of the hourly sweeper. Previous
  behavior: stale actions accumulated indefinitely.
- **#16 CallFire dial failure retry parity.** Dispatcher now emits
  `cancelFailedOutboundCallfireDial` on failure (matches the SMS/RVM
  pattern). Handler registered — 13 total now.

### Inbox polish

- **#9 Auto-responder cooldown filters to auto-sent only.** Cooldown
  math now calls `findLatestOutbound(domain, phone, { autoRespondedOnly:
  true })`. An agent's manual reply no longer starves the bot's next
  auto-response window.
- **#14 Inbox list hides auto-responded threads by default.**
  `buildQuery` applies `aiRecommendedAction: { $nin: ["auto_dnc_confirm",
  "auto_callback_prompt"] }` unless `includeAutoResponded: true`.
  Operators see a real work queue, not bot receipts. Flag flows from
  the route query param through to the repo.
- **#15 Unknown tracking-number warning.** When a CallRail inbound
  can't be resolved to a company AND the payload has no `domain`/
  `company` hint, we now create an `sms-inbound-unknown-tracking`
  review item instead of silently defaulting to TAG.
- **#13 Transcription max-attempts guard.** `MAX_TRANSCRIPTION_ATTEMPTS =
  24` (env-overridable). After 24 hourly `no_recording` attempts, flips
  to `abandoned` status. The hourly `recording-ready-state` resolution
  check treats `abandoned` as resolved, so the retry loop exits cleanly
  instead of running forever.
- **#22 OTP `attemptsRemaining`.** `/auth/send-code` returns it in
  the envelope; `/auth/verify-code` returns it on invalid-code errors.
  Frontend can now warn "2 attempts left."
- **#2 Per-turn message history + per-message dispositions (the big
  one).**
  - New `GET /api/read/inbox/:domain/threads/:workflowId/messages`
    returns full inbound+outbound history with provider status and
    disposition.
  - New `POST /api/commands/inbox/messages/:messageId/disposition`
    with allow-list `{approve, send_as_is, regenerate, dnc_hard,
    dnc_soft, hostile, spam, already_client, wrong_number}`.
  - Frontend hooks `useInboxThreadMessages` + `useInboxMessageDisposition`.
  - `InboxWorkspace.tsx` right pane rebuilt as a bubble thread:
    inbound left / outbound right, provider-status pill under outbound
    (sent/delivered/failed with color), auto tag on bot-sent bubbles,
    classifier tier+confidence pill under inbound, per-message chip row
    (9 disposition buttons) on every inbound bubble, auto-responder
    status chip in the thread header, scrollable (480px max), loading
    skeleton, empty-state fallback to the workflow's latest inbound.
  - Workflow-level actions (Approve / Edit Send / Regenerate / Sleep /
    Wake / Cancel / DNC) preserved unchanged.

## Known deploy-checklist items

1. `.env` needs `TAG_CALL_RAIL_TRACKING_NUMBER=8186865483` and
   `WYNN_CALL_RAIL_TRACKING_NUMBER=3105611009` (currently only the
   generic fallback is set, which makes the server boot fail the
   tracking-number conflict guard).
2. **`RC_SUBSCRIPTION_WATCHDOG_ENABLED` defaults to `false`.** The
   watchdog's renew + recreate paths are gated so Parallel won't
   accidentally become the RC webhook target just because `NGROK_DOMAIN`
   is set. Turn on only when this app is ready to own inbound RC
   traffic. While off: silence detection still runs, event-liveness
   stamping still runs, `/health` shows `subscriptionWatchdog.enabled:
   false`, and manual `POST /api/ringcentral/subscription/check` returns
   409. Queued `renewRingcentralSubscription` jobs dead-letter cleanly
   with a clear reason.
3. `NGROK_DOMAIN` (or prod DNS domain) must point at the actual
   public webhook URL so the watchdog composes the right
   `webhookAddress` — *but this only matters once the watchdog is
   enabled*.
4. `RINGBRIDGE_WEBHOOK_SECRET` must match the secret RC uses for
   verification. If it doesn't, the watchdog will detect the mismatch,
   delete the old sub, and create a new one with the env-configured
   secret on first tick — *again, only once the watchdog is enabled*.
